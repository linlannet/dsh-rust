# 0001 基线说明

## 当前存储

Java 版通过 MyBatis 访问 H2 或 MySQL，保存会话、消息、审批、任务、目标与模型设置。具体表结构以 Java 基线的 `schema.sql` 与 MySQL dump 为准，本文件不复制 DDL，避免两处漂移。

## 迁移原则

1. **先备份**：导出前停止写入，保留原始 H2/MySQL 文件或 dump 的校验和。
2. **单写入方**：切换期间只允许一个 Runtime 写库，不做双写。
3. **事件优先**：先迁移会话与事件，再迁移派生的统计和索引。
4. **可回滚**：迁移工具必须支持回滚到原库，并保留旧版本可启动能力。

## H2 到 SQLite 的注意点

- Rust 驱动不能直接读取 H2 文件格式，必须通过 Java 版导出为中立格式（JSONL/SQL）。
- 字符集、时间精度、布尔表示、自增主键和空值语义需要逐项校验。
- 迁移后校验：会话数、消息数、事件数、每个会话最大 `seq`、终态事件数量。

## 验收

- 同一会话在 Java 与 Rust 中回放，消息顺序、工具调用配对、审批结论一致。
- 中断迁移后可以重新执行，且不会产生重复事件。
- 旧库保持只读可查，直到新库通过验收。
