# 版本规则

## 三个独立版本

| 版本 | 位置 | 示例 |
| --- | --- | --- |
| 契约版本 | `contracts/VERSION` | `1.0.0` |
| 产品版本 | Runtime 构建信息 | `0.3.0` |
| 插件主机协议版本 | `initialize` 协商字段 | `dsh-plugin-host/1` |

三者不得共用同一个版本号，避免“产品未发布但契约已变”或“契约未变但产品升级”的误判。

## 语义

- **MAJOR**：出现不兼容变更，新开 `vN/`。
- **MINOR**：兼容新增字段、事件、错误码、可选能力。
- **PATCH**：修正描述、示例、校验脚本，不改变线上行为。

## 冻结

- 目录一旦随 tag 发布即为 `frozen`，禁止原地修改。
- 需要修正行为时，优先新增字段或事件；确属破坏性变更则开新大版本。
- 草稿阶段（`1.0.0-draft.N`）允许调整字段，但每次调整必须写入 `CHANGELOG.md`。

## 插件宿主协商

- Rust 与 JVM 宿主在 `initialize` 中交换 `protocolVersion`。
- 双方必须支持自身版本与前一版本；不支持的请求返回结构化错误，不得静默降级。
