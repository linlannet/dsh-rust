# 兼容性规则

## 角色约定

- **生产者**：Java Runtime、Rust Runtime、JVM 插件宿主、插件作者。
- **消费者**：desktop、mobile、第三方集成、回放与迁移工具。

## 字段

- 消费者必须忽略未知响应字段。
- 服务端必须忽略未知请求字段，不得因新增字段拒绝请求。
- 响应 schema 使用 `additionalProperties: true`；请求 schema 可对核心对象收紧，但不得依赖未知字段拒绝。
- 不得复用已删除字段名表达新语义。

## 枚举

- API 枚举默认按开放枚举处理：消费者必须有 default 分支。
- SSE 事件名是开放枚举，未知事件记录告警，不得崩溃或中断流。
- 已知事件：`chunk`、`tool_call`、`done`、`error`。

## 事件流

- `seq` 从 1 开始严格递增。
- 每个流恰好一个终态事件：`done` 或 `error`，且必须是最后一个业务事件。
- 取消以 `done` + `finishReason: cancelled` 结束，或返回 `error`，二者不得同时出现。
- 心跳不属于业务事件，不进入 fixture 的 `seq`。

## 允许的归一化

仅限：时间戳、随机 ID、耗时、绝对路径、端口号。

禁止归一化：错误码、错误类型、事件数量、事件顺序、工具名、工具参数、审批结果、终态。

## 破坏性变更

- 删除字段、改字段类型、改字段语义、新增必填字段。
- 修改事件顺序、终态规则、错误码含义。
- 收紧已有合法输入（例如新增更严格的正则）。

破坏性变更必须新开 `v2/`，并保留 `v1/` 至少一个发布周期。
