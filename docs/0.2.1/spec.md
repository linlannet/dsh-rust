# DeepSeek Harness Rust v0.2.1 需求规格

> 版本：`v0.2.1` ｜ 基线：`v0.2.0` ｜ 契约版本：`1.0.0-draft.1`
>
> 主题：**从「能跑」到「能续」** —— 会话与事件落库、进程重启可续跑、运行过程可回放、流式输出内存可控。
>
> **数据声明**：本版**首次引入数据库**（SQLite 单文件），表结构见 §6；不使用外部数据库服务，不引入多租户。

---

# **1. 组件定位**

## **1.1 核心职责**

1. 在 v0.2.0 的 HTTP + ReAct 闭环之上，增加**会话与事件日志的持久化**。
2. 提供**事件回放**读取面：按 `sessionId` 与 `seq` 游标分页读取。
3. 保证**进程重启后可续跑**：同一 `sessionId` 的下一轮请求能读到历史消息。
4. 收敛 v0.2.0 遗留的**流式输出内存风险**：单次运行设置字节预算。

## **1.2 核心输入**

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| Agent 消息请求 | `POST /api/agent/message`、`POST /api/agent/stream` | 与 0.2.0 契约一致 |
| 取消请求 | `POST /api/agent/cancel` | 与 0.2.0 契约一致 |
| 回放读取 | `GET /api/sessions/{sessionId}/events` | **本版新增** |
| 配置 | 环境变量 | 见 §5.9 |

## **1.3 核心输出**

1. 与 0.2.0 一致的阻塞响应与 SSE 事件流。
2. 持久化的会话消息、运行记录、事件日志。
3. 回放端点返回的事件分页结果（`events` + `lastSeq`）。

## **1.4 职责边界**

1. **不做**插件宿主与工具动态加载（顺延 0.2.2）。
2. **不做**审批与权限矩阵（顺延 0.2.3）。
3. **不做**鉴权、多租户、配额（0.2.3+）。
4. **不做**跨机共享存储；SQLite 为单进程单文件。
5. 不改变 SSE 事件名、顺序与「唯一终态」语义。

# **2. 领域术语**

| 术语 | 定义 |
| --- | --- |
| 会话事件（SessionEvent） | 对外可回放的行为记录，含 `eventId`/`sessionId`/`seq`/`type`/`timestamp`/`payload` |
| seq | 单会话内严格递增的事件序号，从 1 开始，跨重启连续 |
| 回放（Replay） | 按 `seq` 升序读取事件并重建会话状态 |
| 续跑（Continuation） | 复用已持久化的历史消息继续下一轮推理 |
| 序列门（Seq Gate） | 分配 `seq` 时的并发保护：进程内按会话加锁 + 库内唯一约束兜底 |
| 输出预算（Output Budget） | 单次运行允许发送的 SSE 业务事件字节上限 |
| 迁移（Migration） | `0001-baseline.sql` 等版本化建表脚本，启动时幂等执行 |

# **3. 角色与边界**

## **3.1 核心角色**

| 角色 | 关注点 |
| --- | --- |
| 运维者 | 数据库路径、磁盘占用、启动迁移失败可诊断 |
| 客户端（DSH-Desktop / 调试工具） | 会话可续、事件可回放、终态可预期 |
| 审计/差分测试 | 事件序列完整、可跨 Rust/Java 比对 |

## **3.2 外部系统**

| 系统 | 关系 |
| --- | --- |
| 模型提供方（DeepSeek） | 与 0.2.0 一致，不参与持久化 |
| 文件系统 | 承载 SQLite 文件与 WAL 附属文件 |
| contracts/v1 | 表结构、事件 schema、HTTP 端点的唯一事实源 |

## **3.3 交互上下文**

1. 启动：加载配置 → 创建/打开数据库 → 执行迁移 → 装配仓储与事件日志 → 监听端口。
2. 运行：ReAct 循环每阶段追加事件；事件写入失败不改变运行结论。
3. 重启：新进程读取同一 `DSH_DB_PATH`，恢复历史消息与事件。

# **4. DFX 约束**

## **4.1 性能**

1. 单 run 事件写入事务数 ≤ 2，避免与模型调用争抢 IO。
2. 开启 WAL；`busy_timeout` 默认 5000 ms。
3. 回放端点单次返回 ≤ 1000 条事件，默认 200 条。

## **4.2 可靠性**

1. 迁移幂等：重复启动不报错、不丢数据。
2. 事件写入失败**降级**：记录 `Error` 事件与日志，运行仍以原 `finishReason` 收尾。
3. 进程异常退出后，已提交事务的事件不丢；未提交的按 SQLite 语义丢弃。
4. 同一会话并发运行仍返回 `conflict`（沿用 0.2.0）。

## **4.3 安全性**

1. 仅监听回环地址（默认），不因持久化放宽网络暴露面。
2. 数据库文件属于运行期数据，不入版本库；不打印密钥与事件正文到日志。
3. 迁移脚本只允许建表/建索引，不允许写入业务数据。

## **4.4 可维护性**

1. 表结构由 `contracts/v1/persistence/migrations` 演进，代码不得内联建表 SQL。
2. 仓储与事件日志均以端口形式定义，`dsh-domain` 不感知 SQLite。
3. 保留内存实现作为测试替身与回滚通道。

## **4.5 兼容性**

1. 0.2.0 的四端点请求/响应结构保持不变。
2. SSE 事件名、顺序、终态语义不变；新增错误码属增量。
3. 不提供 `DSH_DB_PATH` 时使用默认路径，老部署无需改配置即可启动。

# **5. 核心能力**

## **5.1 会话持久化**

### **5.1.1 Business Rules**

1. 会话与消息同事务写入，避免出现「有会话无消息」的中间态。
2. 消息序号 `ordinal` 在会话内严格递增，重复写入同一 `ordinal` 视为冲突。
3. 读取不存在的会话返回 `none`，由上层创建新会话，不抛错。

### **5.1.2 Acceptance Criteria**

1. [写入会话与两条消息后重启进程] → [读回内容与顺序一致]
2. [同一会话重复写入相同 `ordinal`] → [事务失败并回滚，无脏数据]

## **5.2 事件日志持久化**

### **5.2.1 Business Rules**

1. 事件类型覆盖 `contracts/v1/persistence/event-catalog.md` 的 12 类。
2. `(session_id, seq)` 唯一；`seq` 从 1 开始单调递增，跨重启连续。
3. 事件写入使用批量事务；`payload` 以 JSON 文本存储，字段名与 schema 一致。
4. 事件仅追加，不提供更新与删除接口。

### **5.2.2 Acceptance Criteria**

1. [一次工具调用运行] → [产生 `run.started`/`tool.requested`/`tool.completed`/`run.completed` 的有序序列]
2. [并发写入同一会话] → [`seq` 不重号]

## **5.3 回放端点**

### **5.3.1 Business Rules**

1. `GET /api/sessions/{sessionId}/events`，支持 `afterSeq`（默认 0）与 `limit`（默认 200，上限 1000）。
2. 返回按 `seq` 升序的事件数组与 `lastSeq`；分页不改变事件内容。
3. 会话不存在返回 `not_found`，而非空数组。
4. 非法参数（负数、超上限、非数字）返回 `invalid_request`。

### **5.3.2 Acceptance Criteria**

1. [会话有 5 条事件，`limit=2` 连续翻页] → [3 次取完，无重复无遗漏]
2. [不存在的 sessionId] → [`not_found`]

## **5.4 重启续跑**

### **5.4.1 Business Rules**

1. 同 `sessionId` 再次请求时加载历史消息参与推理。
2. 续跑不重放旧事件，新事件 `seq` 从历史最大值继续。
3. 会话执行中的 `active_run` 属运行期状态，重启后不恢复为 `running`。

### **5.4.2 Acceptance Criteria**

1. [第一轮写入内容 A 后重启] → [第二轮模型请求包含 A]
2. [重启后追加事件] → [`seq` 接续历史最大值，不从 1 重来]

## **5.5 SSE 输出预算**

### **5.5.1 Business Rules**

1. 单次运行的业务事件字节数受 `DSH_STREAM_BUDGET_BYTES` 约束（默认 8 MiB）。
2. 超限时停止发送业务事件，补发唯一终态 `error`，错误码 `STREAM_BUDGET_EXCEEDED`。
3. 心跳不计入预算；`seq` 在超限前后保持连续。
4. 阻塞式 `/api/agent/message` 不受预算影响（无流式输出）。

### **5.5.2 Acceptance Criteria**

1. [构造超预算事件流] → [收到终态 `error` 且此前无第二个终态]
2. [超限场景] → [已发送事件的 `seq` 连续无跳号]

## **5.6 存储故障降级**

### **5.6.1 Business Rules**

1. 启动时数据库不可用（路径不可写、迁移失败）→ **拒绝启动**并给出明确错误。
2. 运行期单次写入失败 → 不中断运行，记录 `Error` 事件与日志。
3. 回放读取失败 → 返回 `storage_unavailable`，不返回空数组。

### **5.6.2 Acceptance Criteria**

1. [只读目录启动] → [非零退出码 + 可读错误信息]
2. [运行期写入失败] → [运行仍以原 `finishReason` 结束]

## **5.7 迁移与版本**

### **5.7.1 Business Rules**

1. 迁移脚本位于 `contracts/v1/persistence/migrations`，编号递增。
2. 启动时按编号执行未应用的迁移，全部成功后才对外服务。
3. 迁移只建表/建索引，不做数据回填。
4. 已应用版本记录在库内，避免重复执行。

### **5.7.2 Acceptance Criteria**

1. [空库启动] → [表结构与迁移脚本一致]
2. [已有数据的库再次启动] → [不重复执行、不报错]

## **5.8 契约对齐与回放**

### **5.8.1 Business Rules**

1. 新增端点与事件字段以 `contracts/v1` 为准，先改契约再改代码。
2. `openapi.yaml` 由路由表生成并纳入 CI 校验。
3. fixtures 新增「重启续跑」「事件回放」两组。
4. 契约版本保持 `1.0.0-draft.1`；录制校验全通过后再评估升 `1.0.0`。

### **5.8.2 Acceptance Criteria**

1. [`node contracts/tools/validate.mjs`] → [0 警告]
2. [openapi 再生成] → [与提交版本无差异]

## **5.9 配置与可观测性**

### **5.9.1 Business Rules**

1. 新增环境变量：`DSH_DB_PATH`（默认 `./data/dsh-rust.db`）、`DSH_STREAM_BUDGET_BYTES`（默认 8388608）、`DSH_STORE`（`sqlite` 默认 / `memory`）。
2. 沿用 0.2.0 全部环境变量与默认值。
3. 启动日志打印 `db=`、`model=`、`tools=`、`contract=`、`version=`；不打印密钥。
4. 关闭前 flush 待写事件。

### **5.9.2 Acceptance Criteria**

1. [未设置任何环境变量] → [以默认路径启动并生成数据库文件]
2. [启动与关闭日志] → [不含 `DEEPSEEK_API_KEY`]

## **5.10 测试与质量门禁**

### **5.10.1 Business Rules**

1. 单测覆盖：迁移幂等、`seq` 单调、事务回滚、续跑、预算超限、留存淘汰。
2. 集成测试使用临时文件库，结束后清理。
3. 差分测试：内存实现与 SQLite 实现产生的事件序列逐条一致。
4. 门禁：`cargo fmt --check`、`cargo clippy -D warnings`、`cargo test --workspace --all-features`、契约校验全绿。

### **5.10.2 Acceptance Criteria**

1. [任一测试失败] → [CI 红灯]
2. [新增依赖未在 design §4.1 登记] → [评审阻断]

# **6. 数据约束**

> 与 0.2.0 的「无数据库」约束**显式变更**：本版引入 SQLite 单文件库。

| 表 | 主键 | 关键列 | 说明 |
| --- | --- | --- | --- |
| `session` | `id` | `agent_id`、`workspace_id`、`title`、`status`、`created_at`、`updated_at` | 会话主体 |
| `session_message` | `id` 自增 | `session_id`、`ordinal`、`role`、`content`、`created_at` | 消息历史，`(session_id, ordinal)` 唯一 |
| `session_event` | `event_id` | `session_id`、`seq`、`type`、`timestamp`、`payload_json` | 事件日志，`(session_id, seq)` 唯一 |
| `run` | `run_id` | `session_id`、`agent_id`、`status`、`finish_reason`、`error_json`、`started_at`、`ended_at` | 运行记录 |

1. `seq` 单会话严格递增，从 1 开始，跨重启连续。
2. 所有时间列为 UTC ISO-8601 文本。
3. 事件只追加；不提供删除接口，容量治理留待后续版本。
4. 数据库文件与 WAL 不入版本库。

# **7. 验收标准（版本级）**

1. [空目录首次启动] → [自动创建库与表并可用]
2. [两轮同会话请求 + 中间重启] → [第二轮能续上前文]
3. [事件回放翻页] → [无重复无遗漏，`lastSeq` 正确]
4. [超预算流式输出] → [唯一终态 `error(STREAM_BUDGET_EXCEEDED)`]
5. [全部门禁] → [fmt / clippy / test / 契约校验 全绿]
6. [契约回归] → [0.2.0 四端点行为不变]
